dota-workspace

A monorepo toolchain for building web-component apps.

8 packages, one workspace

The problem

Authoring web components meant repeating the same boilerplate across every app. I wanted the ergonomics of a modern framework without giving up the platform.

My role

Sole author and maintainer. I designed the API surface, the build tooling, and the release pipeline across all packages.

By the numbers

8

packages

1

workspace

01

01 · Approach

A core, then satellites

dota-core defines the component model. Everything else — routing, data, UI — is a thin package that builds on it, so you adopt only what you need.

02 · Build

One pipeline, every package

A single Vite-based toolchain builds, versions, and publishes all eight packages together — so a change to the core ripples out in one command.

03 · Outcome

It runs this site

The portfolio, blog, and this showcase are all built on dota — the strongest proof the ergonomics actually hold up in production.

Why this stack

Web Components

Framework-agnostic and native — apps built on dota outlive framework churn.

TypeScript

The API is only as good as its types; strict typing is the whole selling point.

Vite

Fast enough that the monorepo build never gets in the way of shipping.
