The stack

System-native. Nothing is downloaded, so nothing can arrive late, reflow, or fail offline.

Tracking & leading step —
clamp(min, Xrem + Yvw, max) the rem term is not optional

A pure-vw clamp ignores the user's font-size setting entirely — someone at 200% zoom gets the same headline as everyone else. That fails WCAG 1.4.4. Giving the preferred value a rem component makes part of it track the user's preference. Test this page at 200% zoom: the specimens above must genuinely grow.

Wrong
clamp(2.6rem, 7.5vw, 6rem)
Right
clamp(2.4rem, 1.2rem + 5.333vw, 6rem)
04

Weight

Four weights. The stack has no reliable Light or ExtraBold across all three platforms — asking for one gets a synthesised fake.

Regular — body prose only 400 · running text
Medium — the workhorse 500 · ui, meta, eyebrow, buttons
Semibold — every heading up to title 600 · headings, emphasis
Bold — display tier only 700 · display and display-sm

Why 500 rather than 400 for UI: at 13–15px on a light background, Regular reads thin. Medium holds the same visual density as 400 body copy at 16–18px, so the whole interface reads at one weight even though the numbers differ. Hierarchy comes from the 600/400 pairing and from size — never from adding a heavier weight.

Because the sizes are fluid, the tracking is too. The tokens step at 700px and 1100px — use var(--tr-display), never a literal, or your component will not follow the curve.

06

Leading & measure

Leading follows measure. The longer the line, the more vertical room the eye needs to find the start of the next one.

1.25 — headings

Reads as a single block. Correct for two or three lines of heading, wrong for anything you have to read at length.

1.6 — body

The default for interface text. Comfortable at 16px across a moderate column, and tight enough to keep related content visually grouped.

1.75 — prose

For 18px running across a full 720px column. This is what makes the legal and article pages readable at length, and it should not be tightened.

--measure 720px · roughly 68–75 characters at 18px

This column is exactly one measure wide. Past this point the eye starts losing its place on the return sweep, and the page stops feeling like something you can read and starts feeling like something you have to scan.

Because leading is measure-dependent and the measure collapses on a phone, prose leading steps down to 1.65 below 700px — a 40-character line does not need 1.75.

08

Long-form prose

The article and legal pages run on one .prose block. Everything inside it is defined once.

What the measure buys you

Running text sits at 18px with 1.75 leading inside a 720px column. That combination is not a taste call — it lands at roughly 70 characters per line, which is the top of the range where the eye reliably finds the next line without a conscious effort.

Inline elements

Links take accent-deep and underline on hover, never a weight change. Inline code sits in --tint at 0.9em so it matches the x-height of the text around it rather than the cap height.

  • Paragraph spacing is 1.2em — expressed in em so it scales with the text
  • Headings carry large space above, small below: a heading belongs to what follows it
  • Long URLs and identifiers break rather than blowing out the column

Code blocks

Code scrolls horizontally. It never reflows, because a wrapped line of code is a different program than the one you wrote.

slope     = (max_px - min_px) / (1440 - 360)
intercept = min_px - slope * 360
preferred = (intercept/16)rem + (slope*100)vw
09

Numerals

Proportional digits have different widths. In anything that updates in place or sits in a column, that reads as jitter.

Proportionalwatch the width wobble
₹ 000,000 00:00:00
Tabularevery digit one width
₹ 000,000 00:00:00

Apply font-variant-numeric: tabular-nums to prices, dates, counters, timers, metrics, and every table cell. Prose numbers stay proportional — "about 30 people" is text, not data.

Container response

This card is at the same viewport width whether it sits in a 320px sidebar or a 900px feature slot — but it needs a different heading size in each. Container queries can see that; media queries cannot. Mark reusable blocks with .t-container and use .cq-title inside. Page-level type stays on the ordinary fluid tokens — a hero genuinely is about the viewport.

11

Pairings

Which roles sit next to which. Most type mistakes are pairing mistakes, not size mistakes.

  • eyebrow →.title or .display, never body
  • display →.lead, then body. Never straight into 13px meta
  • title →.lead at most once per section
  • title-sm →body or meta inside a card
  • label →tabular numerals, in a table head or stat block
  • micro →navigation groups and legal fine print only
  • chip →after the content it describes, never before

The gap between two adjacent roles should be at least one full step. A 20px heading above 18px body is not a hierarchy — it is a rendering accident that looks like one.

12

Do & don't

  • neverHardcode a px or rem font-size in a page file
  • neverWrite a font-size media query — the tokens already handle width
  • neverShip a vw-only clamp
  • neverSet a px root font-size — it freezes every rem in the system
  • neverShip a form field under 16px — iOS Safari zooms the viewport on focus
  • neverUse a Tailwind text utility for a role in this table — the two scales disagree
  • neverAdd @font-face, a font @import, or a Google Fonts link
  • neverIntroduce 13.5, 14.5, 15.5 or 16.5px — round to the nearest step
  • neverSet letter-spacing on lowercase body copy
  • neverUse bold or normal keywords for weight

Adding a step to the scale is a human decision. Fourteen entries is deliberate — every addition makes the next choice harder and the drift easier. Two files sharing a stray value is a coincidence. Three is a missing token.

13

Ship checklist

Nothing goes out without all of these.

  1. Typography tokens loaded before page styles
  2. Every text element on a role class or inheriting from body
  3. Zero raw font-size declarations in the page file
  4. Exactly one display-tier element, at the top
  5. Every uppercase run carrying positive tracking
  6. Every heading above 18px carrying negative tracking
  7. Every column of digits tabular
  8. Prose capped at 720px
  9. Every clamp preferred term carrying a rem component
  10. Form fields at 16px or above on touch
  11. Checked at 320px, 768px, 1440px — and at 200% browser zoom
  12. Checked on a landscape phone, roughly 700×360
